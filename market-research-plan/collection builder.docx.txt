Stage 1 — Understand the Existing Website Scope
The Collection Builder is already connected to the client’s website. It analyzes:
Website navigation
Categories and subcategories
Existing collections and PLP pages
It then identifies the broad parent niches already represented on the website.
For example:
Website
├── Toys
├── Sunglasses
├── Eyeglasses
└── Watches
Some stores may have only one broad niche:
Toys
In this case, all existing collections belong under the Toys niche.
Other stores may have several broad niches:
Toys
Sunglasses
Baby Products
Sports Equipment
At this stage, the agent is not recommending which niche to dominate. It is only identifying and organizing the broad catalog areas that currently exist on the website.
Stage 2 — User Selects the Catalog Scope
The agent displays the broad parent niches identified in Stage 1, together with the existing collections under each niche.
For every collection, the agent shows:
Collection name
Number of products or items
Parent broad niche
Total unique products available under the broad niche
Example:
Toys — 3,016 products
├── All Toys — 3,016 products
├── Educational Toys — 419 products
├── Activity Toys — 134 products
├── Board Games — 421 products
└── Remote-Controlled Toys — 36 products
Eyewear — 6,850 products
├── Sunglasses — 4,900 products
├── Eyeglasses — 1,650 products
└── Accessories — 300 products
The user can select:
One existing collection
Several existing collections
All collections under one broad niche
Collections from multiple broad niches
The number of products inside a selected collection does not prevent the user from selecting it.
A collection may contain:
40 products
400 products
4,000 products
This is acceptable because the user is selecting the source catalog and SKUs to be analyzed, not approving the selected collection as a niche to dominate.
After the user confirms the scope, the agent proceeds to deeply analyze the products inside the selected collections.
Stage 3 — Generate Broad Niche Seed Variations
After the user selects the existing collections, the agent analyzes those collections as commercial catalog groups.
For every selected collection, the agent reviews:
Collection name
Collection description, when available
Product count
Broad parent niche identified in the previous stage
The purpose of this stage is to understand the commercial scope of each selected collection and prepare the broad seed variations that will be used in the next stage to check search volume and initial market demand.
At this stage, the agent does not:
Analyze individual products or SKUs
Extract product attributes
Generate detailed sub-niches
Generate long-tail keywords
Build new collection opportunities
Perform full keyword-variation research
Agent process
For each selected collection, the agent:
Reviews its name, description, product count and broad parent niche.
Defines the most accurate canonical niche seed.
Generates the main broad wording variations used to describe the same or closely related niche.
Places every broad seed variation in a separate row.
Labels broader or ambiguous terms clearly.
Prepares the terms for the next stage, where their search volume and initial demand will be checked.
The broad seed variations may include:
Primary market terminology
Common synonyms
Alternative wording
Phrase-order variations
Regional terminology
Relevant spelling variations
Broader market terms, clearly labeled
The agent must not generate styles, product features, materials, brands, use cases or narrow long-tail combinations that are not represented by the selected collection.

The first column must contain one broad seed variation per row.

Column definitions
Broad Seed Variation The term that will be checked in the next stage for search volume and initial demand.

Selected Collection The existing website collection from which the seed family was generated.
Broad Parent Niche The broad website niche identified in Stage 1.

Variation Type The relationship between the variation and the canonical seed:

Scope Match
Exact: Preserves the same commercial meaning.
Close: Commonly represents nearly the same niche.
Broader: Includes the selected niche but also covers other product groups.
Ambiguous: May have another meaning or a different commercial scope.

Stage 3 Purpose
Convert every selected collection into a structured family of broad niche seed variations, with one variation per row, ready for search-volume and initial demand validation.
In the next stage, these terms will be checked for:
Search volume

CPC

Country relevance
Initial commercial demand
The results will then be grouped by Canonical Niche Seed, allowing the user to compare opportunities and choose which niche should proceed to deep research and domination.
Stage 4 — Extract and Filter Keyword Variations
After Stage 3, the user selects the broad seed terms representing the niche or sub-niche they want to research.
The user then provides the following filters:
Target country
Target language
Minimum search volume
Maximum keyword difficulty
Excluded terms
Minimum and maximum word count
Agent process
For every selected broad seed term, the agent:
Calls the Semrush API.
Extracts keyword variations based on the selected filters.
Combines the results from all selected seed terms.
Removes exact duplicate keywords.
Classifies every keyword by search intent.
Separates the keywords into two datasets.
Dataset 1 — Category and Collection Keywords
The agent keeps:
Transactional keywords
Commercial keywords that are suitable for category, subcategory, or collection pages
The agent excludes keywords that are clearly intended for:
Individual products
Specific product models
Informational articles
Navigational searches
Irrelevant topics
The resulting list becomes the clean keyword dataset that will proceed to Stage 5 for embedding, semantic analysis, clustering, and product matching.
Dataset 2 — Informational Keywords
The agent keeps informational keywords in a separate sheet.
These keywords are not deleted because they may later be useful for:
Blog topics
Buying guides
Comparison content
FAQs
Topical Authority content
They do not proceed into the Collection Builder analysis at this stage.

Stage 4 Purpose
Convert the broad seed terms selected by the user into a filtered and deduplicated keyword dataset containing commercial and transactional terms suitable for ecommerce category and collection pages, while preserving informational keywords in a separate sheet.
Stage 4 stops after producing these two clean datasets. Stage 5 will handle embeddings, keyword grouping, semantic matching, and matching keywords with the client’s products.
Stage 5 — Product Matching and Collection Preparation: The engine matches the qualified commercial and transactional keywords with the client’s products and prepares the validated collections ready to be pushed live.
